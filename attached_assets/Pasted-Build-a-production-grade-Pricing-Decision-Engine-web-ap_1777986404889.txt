Build a production-grade Pricing Decision Engine web app for a multi-category e-commerce company like :contentReference[oaicite:0]{index=0}.

Important:
This is NOT a demo or toy app. It must be structured as a scalable, clean, modular system.

Tech stack:
- Backend: Python FastAPI
- Frontend: React (simple but professional UI)
- Database: PostgreSQL
- ORM: SQLAlchemy
- Data handling: pandas
- No AI chatbot UI

Goal:
Create the foundation of a pricing operations platform that:
- ingests pricing-related data
- validates data quality
- stores structured pricing data
- supports SKU-level analysis
- is ready for advanced pricing logic (AI, competition engine later)

Do NOT implement advanced pricing logic yet.
Focus on clean structure, data layer, APIs and UI.

# BACKEND (FastAPI)

Implement APIs:

/products
- GET all products
- POST create product

/sales
- POST upload sales CSV

/prices
- POST upload own prices CSV

/competitors
- POST upload competitor prices CSV

/inventory
- POST upload stock CSV

/data-quality
- GET overview of data issues

# DATA UPLOAD

Allow CSV uploads for:
- products
- sales
- prices
- competitors
- inventory

Validate:

- data types
- duplicate rows
- missing SKU
- negative values

Store upload results in import_jobs table.

# DATA QUALITY CHECKS

Create a service that flags:

- missing cost_price
- missing min_price / max_price
- missing category
- missing stock data
- missing competitor data
- products with very low sales volume
- negative margins

Expose via:
/data-quality endpoint
